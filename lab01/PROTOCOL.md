# CN Chat/1 协议

## 传输和编码

TCP，默认端口 9001。每条帧为 16 字节首部加 payload，整数均为网络字节序。不得把一次 recv 当成一帧；必须先收齐首部，再按长度收齐 payload。EOF 位于帧中间属于截断错误。

|偏移|字节|含义|
|---|---|---|
|0|4|magic，0x434E4554（CNET）|
|4|2|version，1|
|6|2|type，见下表|
|8|4|payload 字节数，最大 16384|
|12|4|sequence，客户端请求从 1 严格递增，服务器事件从 1 全局递增|

payload 为严格 UTF-8；不允许 NUL、CR、非分隔用途的 LF。昵称 1–32 字节，不能包含空格、控制字符或 `/`；正文 1–4096 字节。长度是 UTF-8 字节数，不是汉字数。

## 类型和语义

|值|方向|名称|payload|
|---|---|---|---|
|1|C→S|HELLO|昵称|
|2|S→C|WELCOME|时间 LF 欢迎说明|
|3|C→S|CHAT|正文；向全部在线用户广播，含发送者|
|4|S→C|MESSAGE|时间 LF 发送者 LF 正文|
|5|C→S|PRIVATE|目标昵称 LF 正文|
|6|S→C|DIRECT|时间 LF 发送者 LF 目标 LF 正文；仅两端可见|
|7|C→S|LIST|空|
|8|S→C|USERS|时间 LF 以空格分隔的昵称|
|9|C→S|QUIT|空|
|10|S→C|BYE|时间 LF 原因|
|11|S→C|NOTICE|时间 LF 上线/离线/停机说明|
|12|S→C|ERROR|时间 LF 错误说明|

服务器时间来自本机时钟，格式 `YYYY-MM-DD HH:MM:SS`，使用服务器所在时区。sequence 是事件标识，私聊/欢迎等不会发送给所有用户，因此某个客户端观察到序号间隙并不代表丢消息。客户端请求序号用于发现协议误用，不替代 TCP 的可靠机制。

## 状态和时序

1. TCP 建连 → WAIT_HELLO；首条必须是 HELLO，5 秒内完成首帧，否则断开。昵称冲突返回 ERROR 后断开。
2. HELLO 合法 → WELCOME → ACTIVE，其他在线用户收到上线 NOTICE。
3. ACTIVE 中可 CHAT、PRIVATE、LIST。可恢复的语义错误返回 ERROR，连接保留。错误 magic/version/type/长度/序号/UTF-8 导致 ERROR 后关闭。
4. QUIT → BYE → 服务端关闭连接 → 其他用户收到离线 NOTICE。客户端收到 BYE 后退出。输入 EOF 等同 QUIT。
5. 异常 EOF、连接重置：移除在线用户并通知其他用户；昵称可再次使用。
6. 服务器 `/quit`：停止接入，向在线用户发 BYE，shutdown 唤醒阻塞 recv，等待全部线程结束，最后 WSACleanup。

每客户端一个接收线程；共享用户表及所有服务器发送由同一互斥锁串行化，以保证帧不交叉、各广播的顺序一致。发送设置 2 秒超时，防止慢客户端永久阻塞房间；握手后接收超时取消，允许用户空闲。线程数量上限 64 个并发会话；已完成线程定期回收。

## 边界和安全范围

提供局域网教学聊天，不包含账号认证或加密。默认仅监听 127.0.0.1；跨主机展示显式指定本机局域网地址。TCP 的重传、乱序重组和校验由操作系统实现，应用层协议只负责分帧与业务语义。
