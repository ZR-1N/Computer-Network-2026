\subsection{链路类型不能混用}
\src{pcap_datalink} 给出本句柄数据的链路类型。普通 Ethernet 或 Wi-Fi 适配器在本实验中返回
\src{DLT_EN10MB=1}，可以按以太网头解析；这不意味着抓到了原始 802.11 无线管理帧。
未启用无线监控模式，不把无线信道、重试标志或 Radiotap 等当成已捕获内容。

Npcap 回环通过 Windows Filtering Platform 支持本机流量，通常使用 \src{DLT_NULL}，只有地址族等伪首部，没有以太网源/目的 MAC\cite{npcapdev}。
因此程序对非 DLT\_EN10MB 句柄直接提示错误并退出，不将回环 IP 数据的前 12 字节伪装为 MAC。
离线 DLT\_NULL 合成文件也用于验证该拒绝路径。

\section{数据帧格式与解析规则}\label{sec:frame}
\subsection{以太网必显字段}
对 DLT\_EN10MB，以下偏移均从 Npcap 返回的数据缓冲起点计数，不包含前导码和 SFD。
MAC 按原始字节顺序输出，类型字段按大端解释。

\begin{table}[H]\centering
\caption{题目要求的字段与字节位置}
\begin{tabular}{cllc}\toprule
字节偏移 & 长度 & 含义 & 读取条件\\\midrule
0--5 & 6 & 目的 MAC & caplen $\ge 14$\\
6--11 & 6 & 源 MAC & caplen $\ge 14$\\
12--13 & 2 & 类型/长度字段 & caplen $\ge 14$\\
14 & 1 & 字段之后第一个字节 & caplen $\ge 15$\\\bottomrule
\end{tabular}\end{table}

程序把是否存在一个字段与字段的数值分开表示。例如 ARP 后首字节可能为 \src{0x00}，这仍是实际捕获到的有效数值，不能因为它等于零就显示 N/A。
若捕获长度仅为 14，则 MAC 与类型字段有效，但首字节不存在；若不足 14，则整条标记为短以太网帧。

\subsection{类型字段与长度字段的区分}
IEEE 802.3 长度字段的最大值是 1500；字段值达到 1536（\src{0x0600}）及以上才按 EtherType 解释；1501--1535 是保留区间。
本实验常见 EtherType 为 IPv4（\src{0x0800}）、ARP（\src{0x0806}）、IPv6（\src{0x86DD}）。
不能将所有 16 位数值都称为 IPv4 类型，也不能把某一条样本的首字节固定写入程序。类型数值参照 IEEE 802 Numbers 登记表\cite{ethertypes}。

\subsection{VLAN 的两个不同“首字节”}
对于 \src{0x8100} 或 \src{0x88A8}，偏移 14 开始是 VLAN 控制字段 TCI，之后才是内层 EtherType 和实际负载。
题目要求的“类型字段之后第一个字节”始终显示\textbf{外层字段之后的原始偏移 14}；程序另外显示内层类型、VLAN ID、负载偏移及负载首字节，避免混淆。

例如合成测试字节 \src{81 00 A0 64 08 00 45} 表示外层类型 \src{0x8100}，After 为 \src{0xA0}，TCI 为 \src{0xA064}，VLAN ID 为 100，内层类型为 IPv4，真正 IP 首字节为 \src{0x45}，负载从偏移 18 开始。双标签时继续向后解析；每次至少检查剩余四个字节，循环次数受实际捕获长度限制。
此处 VLAN 是明确标记的\textbf{合成边界测试}，本次真实网卡样本并未捕获 VLAN 标签。

\subsection{截断、字节序与解析范围}
\src{pcap_pkthdr.caplen} 是缓冲区实际可读取的字节数，\src{len} 是原始帧长度。
若 caplen 小于 len，只能在 caplen 范围内读取，并标注 TRUNCATED。不能因为原始帧足够长就读取未捕获的内存。
本程序不强转为带平台填充的头部结构体，使用显式字节操作；因此未对齐缓冲区也能安全解析。

\begin{code}
inline uint16_t read_be16(const uint8_t* p) {
    return static_cast<uint16_t>(
        (static_cast<uint16_t>(p[0]) << 8) | p[1]);
}
// MAC destination: data[0..5]; source: data[6..11].
// Type/length: read_be16(data + 12).
// Mandatory first byte: data[14], only if caplen >= 15.
\end{code}

程序不能假定读取缓冲期限会在没有任何流量时定时唤醒阻塞读取，因此主动使用非阻塞模式\cite{nonblock}。
收到状态 1 时立即处理并打印该帧；状态 0 表示暂时没有数据，等待 10 ms 后重新检查停止条件；状态 -1 为错误，-2 表示离线读取结束或 break 情况\cite{nextex}。
驱动返回的头部与数据指针只在后续读取前有效，程序在本轮完成解析和可选转储，不在下一轮继续引用旧指针。

以下是接收分支的简化核心片段，完整实现还记录计数、判断退出条件和处理可选保存：
\begin{code}
const int status = api.pcap_next_ex(handle, &header, &packet);
if (status == 1) {
    print_frame(++received, *header, packet, json);
} else if (status == 0) {
    std::this_thread::sleep_for(std::chrono::milliseconds(10));
} else if (status == PCAP_ERROR_BREAK) {
    break;
} else {
    throw std::runtime_error(api.pcap_geterr(handle));
}
\end{code}

Q 不需要按回车；Ctrl+C 与 Ctrl+Break 通过控制台处理函数仅设置停止标志，资源由主流程释放。
默认最多显示 20 帧或运行 30 秒；两项均可设为零取消限制。时间使用单调时钟，避免系统时钟调整干扰结束判断。

\subsection{输出设计与可选保存}
人类可读主表固定显示 \src{SRC-MAC}、\src{DST-MAC}、\src{Type} 和 \src{After}，并附时间、捕获/原始长度、协议名称。
额外解释单独放在下一行；VLAN 内层解释不会覆盖主表原始字段。
\src{--json} 提供同一组信息的 JSON Lines，供自动化检查，不改变捕获和解析逻辑。

默认仅在屏幕显示，不打开抓包文件。只有明确提供 \src{--save} 时才调用 \src{pcap_dump_open/pcap_dump} 保存原始帧。
\src{--read} 使用 \src{pcap_open_offline} 复核已有文件，输出明确标为“离线复核”，不冒充实时捕获。
设备列表、捕获句柄和可选转储分别由小型 RAII 资源管理器负责释放；Npcap 驱动、DLL 和第三方安装器不打包进提交文件。

\section{真实捕获结果与逐帧分析}\label{sec:analysis}
\subsection{捕获配置与总体结果}
在实际 Wi-Fi 网卡上设置 \src{icmp and host 10.130.0.1}，只捕获与本机网关有关的 ICMP。

\src{ps_drop} 表示捕获机制因缓冲等原因丢弃的计数；其值为零表示本次句柄没有报告此类捕获丢弃。

三次 ping 均得到应答，是此次请求/应答的观察事实，不能外推为所有网络业务的丢包率。

\section{问题处理、结论与局限}
\subsection{主要问题及解决}
\begin{enumerate}
\item \textbf{驱动存在却无法加载 API。} 原环境缺少配套 DLL。完成官方 Npcap 安装后，以实际 API 调用和物理网卡捕获验证，而不是仅查驱动文件是否存在。
\item \textbf{回环并非 Ethernet。} 捕获之前检查链路类型；非以太网句柄明确拒绝，避免显示没有意义的“MAC”。
\item \textbf{类型字段与后首字节易混淆。} 固定主表的原始偏移，VLAN 内层字段单独展示；以合成测试验证零值、双标签及截断。
\item \textbf{空闲时阻塞导致无法退出。} 使用非阻塞 next\_ex 与短暂等待，持续检查数量、时间及退出标志；无流量和 Ctrl+Break 测试均通过。
\item \textbf{中文路径受系统代码页影响。} 宽字符入口和 pcap\_init UTF-8 模式共同处理，已用中文文件名验证同一真实捕获可重放。
\item \textbf{屏幕输出需要独立核对。} 将可选保存的真实帧与 JSON 字段逐项比较，避免仅看“程序有输出”就判断解析正确。
\end{enumerate}

\subsection{实验结论}
本实验完成 Npcap 网卡枚举、打开、实时捕获、字段显示与正常退出。使用 C++ 直接处理捕获字节，
\ParserTests{} 项解析测试和 \IntegrationTests{} 项集成测试全部通过；实际六个 ICMP 帧的源/目的 MAC、类型字段、字段后首字节与原始 PCAP 完全一致。
默认只输出屏幕，持久化是可选复核功能；交付含源码、可执行文件和使用本人南开模板完成的 LaTeX 报告。

局限是仅对 DLT\_EN10MB 作以太网字段解析，非以太网类型明确拒绝；实际样本来自一张 Wi-Fi 网卡和一次本机网关测试，VLAN/ARP/IPv6 等边界覆盖不能冒充本次真实网卡观测。
统计只反映该捕获句柄和本次测试，不证明物理网络永不丢包。现场运行仍需安装 Npcap，并按实际网卡编号和网络流量选择设备。
